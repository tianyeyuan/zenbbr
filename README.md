## 📖 项目介绍

这是一个经过深度优化的BBR一键加速脚本，采用**三层智能决策**流程：先体检、再建议、后执行，避免无脑升级内核造成不必要的风险。

**核心理念：**
- 🔍 **先诊断**：自动检测系统状态和网络环境，评估 BBR 收益
- 💡 **再建议**：根据诊断结果给出操作建议（直接启用 / 建议启用 / 不建议折腾）
- 🔧 **后执行**：用户确认后才执行操作，所有变更可回滚

## ✨ 功能特性

### 🚀 核心功能

| 功能 | 说明 |
|------|------|
| **智能诊断** | VPS 体检 + 收益评估，自动给出操作建议 |
| **BBR加速** | 启用Google BBR拥塞控制算法，提升网络速度 |
| **内核升级** | 自动升级到最新稳定内核（仅在必要时推荐） |
| **旧内核清理** | 清理多余旧内核，释放/boot空间 |
| **系统优化** | TCP参数优化、网络栈调优 |

### 🛡️ 安全特性

- ✅ 三层决策避免无脑升级内核

- ✅ GPG 校验风险明确警告并要求确认
- ✅ 内核升级前多重安全提示（备份 / 带外管理 / 业务低峰）
- ✅ 所有关键操作写日志到 `/var/log/zenbbr.log`

## 🚀 快速开始

### 一键安装命令

```bash
bash <(curl -sL https://raw.githubusercontent.com/tianyeyuan/zenbbr/main/newbbr.sh)
```

使用 wget：

```bash
wget -O newbbr.sh https://raw.githubusercontent.com/tianyeyuan/zenbbr/main/newbbr.sh && bash newbbr.sh
```

### 使用步骤

**推荐流程（适合所有用户）：**

1. **运行脚本** → 选择 `1` 智能诊断
2. **根据诊断结论操作**：
   - ✅ **BBR已正常运行** → 无需任何操作
   - ✅ **推荐启用** → 诊断中直接一键启用，无需升级内核
   - ⚠️ **可选** → 评估收益后自行决定
   - ❌ **不建议** → 维持现状或考虑更换系统
3. **需要升级内核时** → 选择 `3`（请务必阅读风险提示）
4. **验证效果**：
   ```bash
   lsmod | grep bbr
   sysctl net.ipv4.tcp_congestion_control
   ```

## 🛠 高级用法

脚本支持命令行参数用于自动化场景：

| 参数 | 说明 |
|------|------|
| `--dry-run` | 仅扫描探测，不做任何实际变更 |
| `--yes` / `-y` | 无人值守模式，自动确认所有交互 |
| `--bbr-only` | 安全模式，不改系统源和内核 |
| `--help` / `-h` | 显示帮助信息 |

调用示例：
```bash
# 无人值守，不改源，仅开启 BBR
bash newbbr.sh --bbr-only --yes

# 试运行，查看脚本将执行什么操作
bash newbbr.sh --dry-run
```

> **日志**: 所有关键操作记录在 `/var/log/zenbbr.log`，方便排障。

## ❓ 常见问题

<details>
<summary><b>Q1: 智能诊断都检测了什么？</b></summary>

- BBR 当前状态（已启用/未启用/模块是否加载）
- 内核版本是否支持 BBR（4.9+ 基础支持，5.4+ 最佳）
- 网络延迟评估（通过 ping 检测 RTT，高延迟环境收益更大）
- 虚拟化类型（OpenVZ 无法升级内核）
- 系统兼容性（CentOS 8+ 升级风险极高）
</details>

<details>
<summary><b>Q2: CentOS 8 及以上版本能用吗？</b></summary>

CentOS 8+ 已停服，脚本支持一键配置 Vault 源和 BBR 参数，但**不支持自动升级内核**。
强烈建议迁移到 Ubuntu 22.04+ 或 Debian 12。
</details>

<details>
<summary><b>Q3: 升级内核安全吗？</b></summary>

- ✅ 脚本使用官方源（ELRepo/官方仓库）
- ✅ 保留旧内核，出问题可回退
- ✅ 升级前会检查 /boot 空间和虚拟化类型
- ⚠️ 生产环境建议先在测试机验证
</details>

<details>
<summary><b>Q4: 操作出问题如何回滚？</b></summary>

- **系统源**：备份文件在 `/etc/apt/sources.list.bak_时间戳` 或 `/etc/yum.repos.d/backup_时间戳/`
- **内核**：旧内核默认保留，可通过 GRUB 选择旧内核启动
- **BBR 配置**：删除 `/etc/sysctl.d/99-bbr.conf` 并执行 `sysctl --system` 即可还原
</details>
